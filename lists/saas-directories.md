# Awesome SaaS directories: a small, reviewed launch and listing shortlist

> **Web version:** [saas-directories.html](https://tsingniao666.github.io/nettreeai/saas-directories.html) · [中文](https://tsingniao666.github.io/nettreeai/zh/saas-directories.html)

Looking for **SaaS directories**, **SaaS launch sites**, **AI tool directories**, or places to submit a developer product? This is a deliberately small, reviewed shortlist—not a bulk “submit everywhere” database.

The complete machine-readable source for these entries is [`starter-directories.csv`](./starter-directories.csv). Use this page to choose a sensible first path; use [NetTree](https://nettree.ai) when you need matching against your site, language, market, and evidence rather than a generic list.

## Pick by launch goal

| Goal | Start with | Why it can fit |
|---|---|---|
| Launch a new SaaS or developer product | [Product Hunt](https://www.producthunt.com/posts/new), [BetaList](https://betalist.com/submit), [Hacker News](https://news.ycombinator.com/submit), [Indie Hackers](https://www.indiehackers.com/) | Best when there is a real product story, demo, or founder narrative—not a thin listing. |
| Help buyers compare established software | [AlternativeTo](https://alternativeto.net/manage/add-alternative/), [SaaSHub](https://www.saashub.com/submit), [G2](https://www.g2.com/products/new), [Capterra](https://www.capterra.com/vendors/sign-up), [GetApp](https://www.getapp.com/) | Useful for products with a clear category, comparison context, and buyer-facing positioning. |
| Publish an AI tool | [Toolify](https://www.toolify.ai/submit), [There's An AI For That](https://theresanaiforthat.com/submit/), [Futurepedia](https://www.futurepedia.io/submit-tool) | Only if AI is central to the product and the category is genuinely useful to discovery users. |
| Reach Chinese-language developers or product audiences | [开源中国](https://www.oschina.net/), [掘金](https://juejin.cn/), [V2EX](https://www.v2ex.com/), [SegmentFault](https://segmentfault.com/) | Community and content quality matter more than a generic self-promotion post. |
| Build owned discovery assets | A public GitHub repository and GitHub Pages site you control | Publish useful original documentation, add a contextual website link, then verify the public page. Do not request links in repositories you do not manage. |

## Before you submit a SaaS directory listing

1. Match the destination to your audience, language, and market.
2. Read its current rules and pricing; “free entry” does not mean guaranteed acceptance.
3. Prepare a clear product name, one-line description, category, screenshots, and the exact target URL.
4. Record the action as **Submitted**, not **Live**.
5. Save the final public listing URL and verify whether it contains the link you intended.

Download the free [Backlink Evidence Log](../resources/backlink-evidence-log.csv) if you need a portable way to record that evidence.

## Why this list is short

Large SaaS directory lists often mix active editorial surfaces, paid placement schemes, abandoned domains, and community channels that forbid promotion. We keep this list small so every entry has a public home, a plausible human workflow, stated language/market fit, and no obvious spam-farm signals.

See the [inclusion criteria](./inclusion-criteria.md) before suggesting another directory. If you have one strong, verifiable addition, follow [CONTRIBUTING.md](../CONTRIBUTING.md) and update both the Markdown and CSV sources.
