# SaaS launch and directory submission checklist (free)

> **Web version:** [saas-launch-checklist.html](https://tsingniao666.github.io/nettreeai/saas-launch-checklist.html)

Fork this checklist before submitting a SaaS product, AI tool, or developer tool to a launch platform, directory, review catalog, or community. It is designed to prevent rushed, irrelevant submissions—not to maximize submission volume.

## Product readiness

- [ ] The product has a public landing page that explains who it is for and what it does.
- [ ] The target URL works on mobile and points to the most relevant page, not a generic redirect.
- [ ] The product name, one-line description, category, screenshots, and support contact are ready.
- [ ] Claims in the listing can be supported by the actual product or documentation.

## Destination fit

- [ ] The audience, product category, language, and region match the destination.
- [ ] You read the current submission, editorial, pricing, and community rules.
- [ ] You are not treating a community discussion or third-party GitHub project as a generic backlink form.
- [ ] You know what a successful public listing page would look like and can save its URL.

## Owned GitHub assets

- [ ] The repository is public and contains useful original documentation or project material.
- [ ] The About section and Website link accurately describe the project.
- [ ] The README links contextually to the relevant product or documentation page.
- [ ] Optional GitHub Pages content adds real documentation, examples, or methodology—not a doorway page.

## After publishing

- [ ] Record the public page URL, target URL, anchor text, and date in the [Backlink Evidence Log](./backlink-evidence-log.md).
- [ ] Mark the activity as `checking`, not `live`, until the public page has been verified.
- [ ] Recheck later and record `live`, `lost`, or `needs_review` based on evidence.
