# Backlink Evidence Log (free template)

Download or fork [`backlink-evidence-log.csv`](./backlink-evidence-log.csv) to keep one defensible record of where a link was published, what it points to, and whether it is still publicly verifiable.

This is a **generic CSV template**, not a promise of rankings or a list of places to submit. The two rows are illustrative; replace them before using the file.

## What to record

| Field | Why it matters |
|---|---|
| `public_page_url` | The exact public page that should contain the link. |
| `target_url` | The page on your own site being linked to. |
| `publishing_method` | For example `self_published`, `editorial`, `directory`, or `community`. |
| `page_type` / `link_location` | Makes later review possible without relying on memory. |
| `anchor_text` / `rel` | Captures the visible context and link attribute when known. |
| `published_at` / `last_checked_at` | Separates the act of publishing from later verification. |
| `verification_status` | Use `checking`, `live`, `lost`, or `needs_review`—not wishful thinking. |

## A responsible GitHub example

For an owned GitHub asset, record the public repository or Pages URL only after you publish useful, original content. A legitimate path can include:

1. A public repository with real project documentation.
2. A repository About description and Website URL.
3. A contextual link in the README.
4. Optional GitHub Pages documentation that links to the relevant page on your site.

Do not use this template to request promotional links in repositories you do not manage. A GitHub repository is an owned-public-asset path, not a third-party backlink submission channel.

## How NetTree uses the same idea

[NetTree](https://nettree.ai) keeps **Submitted** (an activity) distinct from **Live** (a publicly verified result). This template is a lightweight, portable starting point; the product adds site context, matching, queues, and verification.
